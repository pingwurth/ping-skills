# 代码与设计规范参考（命名 / 码值 / 设计面）

设计文档中的每个标识符与码值都是实现阶段的契约——类名、变量名、表名列名、接口路径、参数名、状态码、错误码。命名或码值不合规范，实现阶段要么照抄错的、要么偏离文档。本文约束两份文档（需求分析 / 详细设计）中的命名与码值定义（对应 SKILL.md 硬约束 9）。

## 优先级（冲突时以高者为准）

1. **目标库正式规范文档**：kb-scan 自动探测到的（如 docs/开发规范.md、CONTRIBUTING.md），或用户在 intake 给出并经 `kb-scan --standards <路径>` 登记的（团队开发规范 / SQL 规约 / 错误码规范等）。
2. **目标库事实惯例**：既有表名列名、既有枚举与常量、既有错误码与响应包络、既有缓存 key——从代码 / 迁移脚本 / schema 查到的就是事实（记 `q-add --facts`，写进「现状与事实调研」节）。
3. **本文缺省基线**：目标库查不到相关惯例时才用。

与基线不同时**遵循 1/2、不遵循基线**；目标库内两种写法并存（如新表 t_ 前缀有无不一）确需拍板的，进台账提问（dimension 取 data-model / api）。

## 调研清单（analyzing 阶段先查，结果记 --facts）

| 调研面 | 查什么 | 常见入口 |
|---|---|---|
| 数据库 | 表名前缀与风格、列名风格、审计列（create_time / upd_time 等）、索引命名、字典表 | 迁移脚本目录、schema 文件、实体类 |
| 枚举与常量 | 枚举类型命名（如 OrderStatus）、值类型（数值 / 字符串）、值风格（UPPER_SNAKE / 01 02 03）、常量归属类 | 枚举类、constants / 常量接口 |
| 错误码 | 统一错误码类、响应包络（code/msg/data）、业务码分段规则、HTTP 码用法 | 异常体系、统一返回体 |
| API | 路径风格（kebab / 下划线）、资源单复数、参数命名（camel / snake）、分页参数名 | 既有 controller / 路由定义 |
| 缓存 | key 前缀与分隔符、TTL 常量归属 | 缓存工具类、CacheKey 常量类 |
| 消息与配置 | topic / 事件命名、配置 key 风格 | MQ 生产者、应用配置文件 |
| 前端（shape=web） | 组件命名、路由命名、store 模块命名 | 既有页面目录 |

知识库可用时一发查询可覆盖多面（codegraph：codegraph_explore 找枚举 / 常量 / 错误码类；repowise：search_codebase）。某面查不到既有惯例时用基线，并在「现状与事实调研」记一句"目标库无既有惯例，采用 coding-standards 基线"。

## 命名基线（目标库无既有惯例时）

| 命名面 | 基线 | 示例 |
|---|---|---|
| 类 / 接口 / 枚举类型 | UpperCamelCase，名词；枚举名不带 Enum 后缀 | `ExportTask`、`ExportStatus` |
| 方法 | lowerCamelCase，动词开头 | `createExportTask` |
| 变量 / 参数 | lowerCamelCase；布尔用 isXxx / hasXxx，避免否定式 | `taskId`、`hasMore` |
| 常量 / 枚举值 | UPPER_SNAKE_CASE | `MAX_RETRY`、`PENDING` |
| 包 / 模块 | 全小写单词 | `export` |
| DB 表 | snake_case，不用复数；业务前缀仅当目标库已有 | `export_task` / `t_export_task` |
| DB 列 | snake_case；主键 `id`；时间列 `xxx_at`；布尔列 `is_xxx`；金额列注明单位与精度 | `order_id`、`created_at` |
| 索引 | `idx_<表>_<列>`、唯一 `uk_<表>_<列>` | `idx_export_task_order_id` |
| API 路径 | kebab-case 复数资源 + 版本前缀；方法语义即 CRUD | `POST /api/v1/export-tasks` |
| API 参数 | JSON 体与 query 参数 camelCase（与变量一致） | `{"orderId": "O123"}` |
| 缓存 key | 冒号分层 `应用:模块:业务:标识`，不用空格与中文 | `demo:export:task:123` |
| 消息 / 事件 | topic 小写点分；事件名用过去式 | `order.export.created` |
| 配置 key | 跟随框架惯例（Spring 用 kebab-case） | `export.max-retry` |

同一文档内一个概念只有一个名字：新名字先进「术语表」（别名进 Avoid）；中文名与代码名并用时，首次出现写"中文名（`codeName`）"，其后只用其一。

## 码值定义规范

码值 = 状态 / 类型 / 原因 / 渠道等用有限离散值表达的字段。**每个码值字段都必须给全码值表**——只写"状态：待处理/处理中/已完成"而不给码值，实现阶段必然自行编码。

码值表格式（放数据库设计的列说明处，或紧随其后的独立表格）：

| 码值 | 枚举名 | 含义 | 备注（流向 / 触发 / 终态） |
|---|---|---|---|
| 0 | PENDING | 待处理 | 初始态，创建即入 |
| 1 | RUNNING | 处理中 | 领取任务时置入 |
| 2 | DONE | 已完成 | 终态 |
| 3-8 | — | （预留） | 扩容用，不分配 |
| 9 | FAILED | 失败 | 终态；重试耗尽置入 |

规则：

1. **枚举名与码值双写**：枚举名 = 代码中的枚举常量（UPPER_SNAKE），码值 = 落库 / 传输的实际值（数值或字符串，按目标库）。只写其一等于没定义。
2. **同字段类型统一**：全部数值或全部字符串，不混用；字符串码值写清大小写与长度（如 `CHAR(2)` 的 `"01"`）。
3. **分配有序且留隙**：连续分配、跳段预留（如 9x 段留给异常类）；预留段在码值表标"预留"。
4. **语义只增不改**：已发布的码值不改含义、不复用、不删除；废弃标"废弃，仅存量数据"。
5. **初始态与终态明确**：每个状态字段写明创建时的初始值与全部终态；状态迁移与核心逻辑的 stateDiagram 用同一批枚举名（文档与图一致）。
6. **布尔语义**：基线用 `is_xxx` 列 + BOOLEAN；目标库用 0/1 码值时遵循之，并把 0/1 写进码值表（0=否，1=是，不引入 2）。
7. **标准码值引标准号**：币种 ISO 4217、国家 ISO 3166、证件类型等有现行标准的直接引标准，不自造、不重排。
8. **错误码分层**：HTTP 状态码只表传输 / 权限语义，业务错误用业务码；业务码分段规则按目标库（无既有规范时建议 `<域>.<场景>.<原因>` 字符串或分段数字，全文档统一一种）；接口表"错误码"列两者都给（如 `409 / EXPORT.TASK.DUP`）。

## 落文档要求（受约束的章节）

| 章节 | 要求 |
|---|---|
| 术语表（analysis） | 概念的唯一名字从这里出发；代码名与中文名的对应在此定 |
| 核心逻辑说明 | 状态机状态名 = 码值表的枚举名 |
| 接口设计 | 路径 / 参数 / 错误码按本文基线或目标库惯例 |
| 数据库设计 | 表 / 列 / 索引按本文；每个码值列给出码值表或明确引用 |
| 缓存设计 | key 规约按本文（分层 / 前缀 / TTL 单位） |
| TDD 测试用例 | Then 断言用同一批码值与枚举名（不新造同义词） |

设计文档确认前自查一遍：全文出现的标识符是否都经得起"目标库有没有同样的写法"这一问——经不起的，要么改回目标库惯例，要么在「现状与事实调研」记录偏离理由。
