本模块是一个 Claude Code Skill，采用「LLM + 确定性脚本」分阶段流水线架构，由 `CLAUDE.md` 与 `SKILL.md` 定义 6 步工作流：
- 第 1 步（LLM）产出 `sensors.json`，受 `sensors.schema.json`（JSON Schema draft-07）约束，描述项目埋点范式、调用链、entry_functions 及 SDK API。
- 第 2 步 `scripts/extract_entries.py` 从 `paradigms[].entry_functions` 提取 grep 正则生成 `entry.txt`，支持可选 `--audit` 模式扫描代码库发现遗漏入口函数与未覆盖的 SDK API 调用。
- 第 3 步 `scripts/locate_call_sites.py` 用 ripgrep（无则回退纯 Python）按正则搜索目标仓库，按 `(file,start_line)` 去重并合并多 pattern 命中，自动排除 wrapper/hook 函数体区间（基于花括号平衡计算），输出 `call_sites.json`；执行前强制检查 `entry.txt` 中的 `# CONFIRMED` 人工确认标记。
- 第 4 步（LLM）逐条读取 `call_sites.json` 追踪字段取值并追加写入 `sensors.csv`。
- 第 5 步 `scripts/check_report.py` 校验 CSV 行数≥调用点数、file 定位有效、禁止动态占位符，输出 `check_report.txt` 与 `resolution_report.csv`。
- 第 5.5 步 `scripts/review_report.py` 对 CSV 做结构校验与字面量比对，追加 `illegal_reason` 列供第 5.6 步 LLM 复核。
- 第 6 步 `scripts/report_manager.py` 将 CSV 归档到 `.agent/sensors-analyze/reports/sensors_YYYYMMDD_HHmmss.csv` 并与上一版本比对差异，输出 `diff_report.txt`。

所有脚本仅依赖 Python stdlib，共享 `scripts/utils.py` 提供统一日志配置（文件日志 + stderr 重定向）、`next_step` 唯一 stdout 输出约定、以及 ripgrep 可用性检测。数据契约集中在 `sensors.schema.json` 与固定 CSV 表头之间，脚本间通过 JSON/CSV 中间产物解耦。
