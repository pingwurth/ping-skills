模块采用「编排层 + 多子脚本 + 公共库」的三层结构：
- 编排层 `scripts/main.py` 通过 `ThreadPoolExecutor(max_workers=4)` 将八个步骤组织为四条并行链路（A: 日志扫描→变更检查；B: @ToString 检查；C: 字段提取→敏感词检查；D: POJO 注释检查→深度分析），统一汇总计数、生成 HTML 报告并依据 `--fail-on` 返回退出码 0/1/2。
- 子脚本层每个文件对应一个独立可执行步骤（`java_log_scanner.py`、`check_log_print.py`、`check_tostring_annotation.py`、`extract_java_fields.py`、`check_sensitive_word.py`、`check_pojo_comments.py`、`analyze_sensitive_fields.py`），通过 `subprocess.run` 由 main 调用，各自负责单一职责并通过 stdout 中的 `SUMMARY:` 行向主流程回传计数。
- 公共库 `scripts/common/` 提供共享能力：`paths.py` 定义产物文件名常量与输出目录解析；`git_utils.py` 封装 git diff/分支校验；`java_lexer.py` 实现 Java 词法分析（屏蔽注释/字面量后迭代类与字段）；`pojo_config.py` 解析 `rules/pojo.config` 判定 POJO 文件；`dictionary.py` 加载四层词典（whitelist > blacklist > core > extended）；`errors.py` / `failures.py` 提供结构化错误码与失败文件分片合并机制。
- 配置数据按类型隔离：`rules/` 存放 JSON/INI 规则（`log-scanner.json`、`sensitive-field-rules.json`、`pojo.config`），`dictionary/` 存放分层词典与英文词汇表，`checkstyle/` 内嵌 Checkstyle 13.7.0 jar 及其 SHA256 基线用于 POJO 注释检查。
- 依赖方向单向：子脚本 → common → 外部命令（git/java/checkstyle），main 仅编排不执行业务逻辑；CI 集成通过约定产物文件路径与退出码契约完成。
