# 写作指南(writing-guide.md)

中文行文, 标识符/路径/命令保留原文。标题自拟, 不要照抄英文说明当标题。
两种风格的页面契约(`plan` 的 `style:` 决定, 门禁见 validation.md):

## 引用格式(两风格共通, 机器校验)

- 行级: `[path.py:15-30](file://path.py#L15-L30)` — 显示文本无 `L` 前缀,
  URL 片段有; 行范围必须真实存在(差一会被 --fix 钳位, 越界是错误)。
- 整文件: `[path](file://path)`。
- **只引用你实际读过的文件**(声明源 + 至多 3 个额外文件, 额外的写进报告)。
- 负面断言(D14): 「未发现/不存在 X」必须 ls AND grep 双重验证(或两种拼写),
  在句中说明检索范围, 命令与输出贴进报告。

## concise 页(Qoder 口径)

- H1 == 计划标题; 若干 `##` 节按 article_type 用途清单组织。
- **不要写** `<cite>` 块、`## 目录`、`## 结论`(发布层注入/添加)。
- 每个 `##` 分析节末尾给 `**章节来源**`; 每张 mermaid 图后给 `**图表来源**`
  (缺了在 concise 只是警告, 但省的是你自己的重写轮)。
- 父页聚合子页 summary/key_topics 并链接, 不复述子页内容。
- mermaid: 默认主题、带空格标签用引号、`<br/>` 换行、字母数字下划线节点
  id、无 `:::class`/`classDef`。

## deep 页(repowiki 口径)

- 400–520 行; 自带 `<cite>**本文引用的文件**</cite>` 块(集合必须与正文
  引用集合一致); 5–8 张 mermaid; 引用链接按页面类别分档(见 validation.md)。
- 每节末尾 `**章节来源**`、每图后 `**图表来源**` 为错误级要求。
- `templates/page.md` 是九节骨架(引言/项目结构/核心组件/架构总览/详细组件
  分析/依赖关系分析/性能考量/故障排查指南/结论); 计划页可能带
  `required_sections` 覆盖。
- 不要为凑分档垫引用, 也不要为压分档裁承重引用。

## 模块速查表(module_sheet)

- concise: 1–3 句, 无 `##` 小节、无 file:// 链接、无图 —— 综合记录,
  正文页"拿来用"而不是重推导。
- deep: 3–8 句/条目, 至少 1 条行级引用(D16), 末尾 `**章节来源**`。

## 知识卡(card)

- YAML frontmatter 必须: `kind`(== 计划 kind)、`name`(== 卡片标题);
  无 H1。
- 体系类(configuration_system/build_system/dependency_management/
  error_handling/logging_system/frontend_style): 五段式
  1.总体方案/2.关键文件/3.架构与约定/4.约定与约束/5.局限; 标题用
  「体系名+构成要素」事实短语, 不用裸类别名。
- `business_term`: `### 词条` 式 —— 每词 `- 定义：…` + `- 别名：…`。
- deep: ≥3 条行级引用(D16 错误级); 模板见 `templates/card-*.md`。

## 永远不写

- 生成物/第三方/构建输出(点名其生成器即可); 密钥/令牌(环境变量只写名字)。
- 编造的 API/文件/行为。骨架目录的 README 规划一律标「声明」,
  与「实现现状」分开(D8)。
- 手工编号标题、`####` 以下深层标题、代码栅栏包裹整篇。
